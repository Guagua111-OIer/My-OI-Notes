然后就得答案了。（不开 long long 见祖宗）

P8814 [CSP-J 2022] 解密 （CSP-J T2 decode）

第一次遇见这么难的 T2。

简化一下题目中的式子，就是求正整数 p、q 满足 pq = n（设为 1 式），ed = (p - 1)(q - 1) + 1。先简化第二个式子：

ed = (p - 1)(q - 1) + 1
ed = pq - p - q + 1 + 1
ed = pq - p - q + 2
ed + p + q = pq + 2
p + q = pq - ed + 2
p + q = n - ed + 2 //结合 1 式

接下来把化简的这个式子与 1 式放在一起：
pq = n
p + q = n - ed + 2（设为 2 式）
好像不能继续求解了，这时我们来看看 p - q 与 p + q（以下 a ^ 2 代表 a 的平方、sqrt(a) 代表根号 a）

(p + q) ^ 2 = p + 2pq + q
(p - q) ^ 2 = p - 2pq + q
(p + q) ^ 2 - (p - q) ^ 2 = 4pq
(p - q) ^ 2 = (p + q) ^ 2 - 4pq
p - q = sqrt((p + q) ^ 2 - 4pq) //设为 3 式

通过 p - q 与 p + q 可以求出 p（p >= q）

p = 2p / 2
  = ((p - q) + (p + q)) / 2
  = (sqrt((p + q) ^ 2 - 4pq) + (p + q)) / 2 // 结合 3 式
  = (sqrt((n - ed + 2) ^ 2 - 4n) + (n - ed + 2)) / 2 //结合 2 式

求出 p 后 q 就等于 n - ed + 2 - p 啦！

这样的解法时间复杂度 O(1)，稳过 k <= 1e5 的数据数量，拿下满分。最后实现是要考虑细节的处理：

1. 不开 long long 见祖宗
2. p = 0（判断即可）
3. p = 无理数 （带入式子验证一遍即可）
4. p = 虚数 （sqrt 虚数会返回 NaN，强制转 long long 值为 0，被处理过了，所以不用考虑）

P1057 [NOIP2008 普及组] 传球游戏

其实是一道简单的 dp，不过自己竟然没自己想出来，实在可惜。
首先分析样例：
我们将三个同学编个号，再做成一个环。我们用数字代表每个同学得球的可能性。（设小蛮为 1 号）

编号:   1 2 3 1 2 3
        -----------
第一轮: 0 0 0 1 0 0
第二轮: 0 1 1 0 1 1
第三轮: 2 1 1 2 1 1

很明显，小蛮有 2 种情况得球（1 -> 2 -> 1，1 -> 3 -> 1）。而二号有一种（1 -> 3 -> 2），三号也有一种（1 -> 2 -> 3）。
容易发现我们在推导时每一种同学在这一轮中的可能性 = 左边同学在上一轮中的可能性 + 右边同学在上一轮中的可能性。
也很好证明，毕竟只有他左边和右边能传到他，所以要么从左边传，遵循左边的可能性，要么从右边传，可能性与右边一样，左边或右边，用加法原理，就是左边可能性 + 右边可能性。注意一定是上一轮的左右两边，否则可能会导致一轮连续传多次的情况。（这里不能压成 1 维，因为 1 维有后效性），最终的转移方程为：f[i][j] = f[i - 1][j - 1] + f[i - 1][j + 1]。其中 f[i][j] 表示在第 i 轮中第 j 个人的得球概率。在实际处理时要特殊判断 1 号与最后一号的情况，因为是一个环，1 号的左边是 n 号，n 号的右边是 1 号。
然后就 A 了这道 dp 题。

P2758 编辑距离

考虑使用 dp 来解决。
设 dp[i][j] 为字符串 A 的前 i 个转化为字符串 B 前 j 个的最小次数。则有两种情况：
- a[i] == b[j]，此时不需要进行任何操作，dp[i][j] = dp[i - 1][j - 1]
- a[i] != b[j]，dp[i][j] = min(dp[i - 1][j], dp[i][j - 1], dp[i - 1][j - 1])。相当于 min(删除，添加，替换)。
然后就 A 了。

P3467 [POI 2008] PLA-Postering
大意：有 n 个长 d[i] 宽 w[i] 的矩形在地上放在一起，求至少使用多少个矩形能将他们正好覆盖。
首先 ans 最大就是 n，因为完全可以每个矩形单独一个矩形覆盖。然后如果不考虑宽度（事实上宽度与答案半个估值的关系都没有）考虑 i 和 j 什么情况下可以被相同的一个矩形覆盖住。
1. i ~ j 范围内所有矩形高度相等。

e.g.
+--------------+ ## #
|##############| ####
|##############| ######
|##############| #######
+--------------+
  ^                      ^
  i                      j

2.i + 1 ~ j - 1 范围内的所有矩形都不低于 i 和 j 且 i、j 高度相等。

e.g.
  #    #    #    #     #
  ##  ##  #        ##         #   #
  ####### ##  #      #   # # #   #
+---------------+ # ## ## # #  ##
|###############| ######### #####
|###############| ###############
+---------------+
 ^                        ^
 i             j


如果说恰恰相反：

         #
       # #          #
 #   ##  ##  #     ##
 #   ######### ##
+-------------+
|#############|
+-------------+
 ^           ^
 i           j

可以看到虽然 i 和 j 高度相等（i = j = 3），但是因为 i 和 j 之间有比 i 和 j 小的，所以 i 和 j 不能被同一个矩形覆盖。
换句话说，在能否一起被覆盖以减少矩形数量这件事上，高度矮的最有决定权。
所以可以看到，每当我们枚举到一个矩形，那么他前面比他高的就一点作用都没有了，直接扔到垃圾桶。那么这样子很显然我们最后的序列一定是从矮到高单调的。既然每次都是对序列尾部操作，序列里越靠前越宁静，所以很明显单调栈即可。每次单调栈，枚举到新元素，栈顶比他高二话不说栈顶直接扔垃圾桶（stack.pop()），最后压进栈顶，如果这个新元素与栈顶的高度一毛一样，ans--（可以一起被覆盖以减少矩形数量），然后继续 pop，直接 AC。

P1045 麦森数
温馨提示：不是正解，不是正解！！！（不过算了，时间复杂度与空间复杂度都正确，算是另一种解法）

首先解决第 1 问。2 的幂的特征是尾数是 2, 4, 8, 6，不可能是 0，所以题目求的 2 ^ n - 1 与 2 ^ n 的位数是相同的！推一推柿子，我们考虑到 10 ^ n 有 n + 1 位，而 n = log10(10 ^ n)，所以 10 ^ n 有 log10(10 ^ n) + 1 位。故 x 有 log10(x) + 1 位，那么 2 ^ n 也有 log10(2 ^ n) + 1 位，根据对数的基本性质，这个柿子可以转化为 2 ^ n 有 log10(2) * n + 1 位（向下取整）。（现实中请强制转换为 int，因为对数的结果是小数）
第 1 问解决，看第 2 问，直接 1 << n - 1 肯定不行，肯定会爆炸（连 n 都要开 unsigned long long，你还指望这个）所以我采用了与高精相似的数组。然后将第 1 位设为 1，不停乘 2，乘 n 次即可。不过这样会超时，如果每次都乘很大的数，数组就会爆炸，于是在我不懈的计算下，得到了一个既不会超时又不会爆炸的黄金值：2 ^ 60。算一算，n 有 3100000，3100000 / 60 = 51666，不可能超时。每一位最大是 9，9 * 2 ^ 60 只有 1.0376293541461623e+19，开 unsigned long long(1.84467440737096e+19) 正好装下，嘿嘿，果然数学是 YYDS（划掉）。每次每个数字的二进制都直接挪 60 位（就是乘 2 ^ 60），如果剩下 n 不够 60 就挪 n 位，然后处理进位，每轮循环 n - 60（因为每次都挪了 60 位）。最后减一（一定要减一！答案要求 2 ^ n - 1），然后按照格式输出就可以。

ABC397 D - Cubes
神级数学题，无题能敌。

题目就非常数学，给你一个 N（大的离谱，只有 long long 才能存），求满足 x ^ 3 - y ^ 3 = N 的任意一组 x 与 y，无解输出 -1。
推导过程如下，首先对 x ^ 3 - y ^ 3 一顿猛拆：
N = x ^ 3 - y ^ 3
  = (x - y)(x ^ 2 + xy + y ^ 2)

将 x - y 设为 a，将 x ^ 2 + xy + y ^ 2 设为 b：
   x ^ 2 + xy + y ^ 2 > x ^ 2 - 2xy + y ^ 2
=> x ^ 2 + xy + y ^ 2 > (x - y) ^ 2
=> b >= a ^ 2
=> N = ab, So N >= a ^ 3
=> a ^ 3 <= n

这样子就方便了，无论 N 有多大，哪怕 long long 才能存，在三次根前还是显得很弱小，所以只要能求出 x y 与 a 之间的关系，就可以通过直接枚举 a 来通过本题！
于是……

   N = ab
=> b = N / a
   a = x - y
=> x = a + y
   b = x ^ 2 + xy + y ^ 2
=> b = (a + y) ^ 2 + (a + y)y + y ^ 2 // 换元
=> b = (a ^ 2 + 2ay + y ^ 2) + (ay + y ^ 2) + y ^ 2
=> b = a ^ 2 + 3ay + 3y ^ 2
=> b = 3y ^ 2 + 3ay + a ^ 2
=> 3y ^ 2 + 3ay + a ^ 2 - b = 0

套一套求根公式……
[ax ^ 2 + bx + c = 0]
[3y ^ 2 + 3ay + a ^ 2 - b = 0]
a: 3
b: 3a
c: a ^ 2 - b

开求！
y = (-b +/- sqrt(Δ:(b ^ 2 - 4ac))) / 2a
x = a + y
将 a b c 的值带入后求值即可！！！AC！！！

P1763 埃及分数

紫色的搜索！！！！！！！！！！！！！！！！！！！！
Colour: Purple（省选 / NOI-）
Algorithm: Deep First Search, DFS（深度优先搜索）
没错我还是认真的

老规矩，做题先得裸搜来理解题意，但是我们裸搜时遇到了亿点点问题：埃及分数万万千，可以使用 10，100，1000，甚至无穷大个埃及分数凑。所以问题1：没有搜索范围。
那既然搜索范围可以无穷，那么一路走到底的深度优先搜索肯定没救了（因为根本撞不了墙，回溯不了！爆堆栈）
那就一层一层搜的广度优先搜索呗。可是，要知道，这棵搜索树不仅深度没限制，广度也可以无穷，因为你并不知道眼前的这些埃及分数哪些不应该选，而埃及分数又有无穷个，所以广度可以无穷，广度优先搜索也一败涂地（因为不知道何时弹出元素，只知道加入新元素！爆队列）
那咋办呀？？？

既然没有限制，我们就手动限制！
我们将限制深度一步步抬高，从 1 到 10，并且限制下一层的埃及分数必须比上一层小（分母比上一层大），那么这时，深度的限制设为 dep。
深度的限制很明显，那广度的限制呢？
由于最后要凑出 a / b，再加上我们越来越小的限制，可以看到，设当前埃及分数为 1 / i，所在层数为 h，那么到最后，埃及分数不会超过 1 / i * (dep - h + 1) = (dep - h + 1) / i（每一层不超过 1 / i，还剩 dep - h + 1 层）带上可行性剪枝的思想，我们的凑出分数为 a / b，而计算过后能凑出的分数为 (dep - h + 1) / i，那么 (dep - h + 1) / i 必须不小于 a / b。所以枚举的子节点必须小于 (dep - h + 1) * a / b，这就是我们广度上的限制。
所以，我们成功的把一个无限的问题变成有限的问题了，接下来只需要枚举深度的限制从 1 到 10，DFS 即可，细节我就不讲了。

这种将无限的搜索变成有限的搜索的算法被称为：
Iterative Deepening Seach，IDS  或者
Iterative Deepening Deep-first Seach，IDDFS
中文名：迭代加深搜索。
一种基于深度优先搜索的、新的搜索算法。

ABC403 D - Forbidden Difference
这道题我也没想到，是动态规划！！！
对于 d = 0 的情况，我们直接去重就可以，具体做法就是统计一共有多少个不同的数字，这些数字各取一个保留，剩下的直接删掉。
d != 0 的话，情况就复杂很多了，咱们直接 开挂（划掉）动态规划。
一个树可以被表示成 k * d + u 的形式，我们的 d 就是输入的那个，k 和 u 则是算出来的。可以看到，(k - 1) * d + u 和 k * d + u 是刚好差 d，于是我们就大循环枚举 u 小循环动态规划 k：
定义：设 dp[k][0] 表示当不保留 k * d + u 时我们最多能保留多少，dp[k][1] 表示保留 k * d + u 时我们最多能保留多少。
转移：dp[k][0] = max(dp[k - 1][0], dp[k - 1][1]);
不选 k 我随你的便，因为怎么选都不会不合法。
转移2：dp[k][1] = dp[k - 1][0] + cnt[k * d + u];
不能同时选 k 和 k - 1，因为他们差 d，不能同时保留。保留 k 就不能保留 k - 1，同时要加上 k 在数列里出现的次数。
初始化：dp[0][0] = 0, dp[0][1] = cnt[u]; 这个很显然
答案：n - max(dp[k - 1][0], dp[k - 1][1]); 保留最多的即可，注意题目问的是删多少个，所以要用 n 减。

做完以上这些，你就 AC 了！！

        if (vis[v]) continue; //我们不能访问重复的节点
        dfs(v, !f);
        //第一个参数表示下一步到 v
        //第二个参数对 f 取反，如果 f 是白，那么下一个就是黑，反之亦然，解决了
        //相邻的元素不能同色的需求
    }
}

那么现在你大概已经懂了二分图的用法，回来看题，会发现我们只要对每个连通块染色，就可以得到答案。为什么呢？因为题中的 A 校学生和 B 校学生的朋友关系汇成了一张无向图。题目描述说只有异校学生才会交友，这个图中也只有异色节点才会相连。题目说要求无向图 B 校的规模，就是说求白点最多会有多少个（注释 orz 下面的部分）。我们只需要枚举每个连通块（因为有可能会出现图不连通的情况），对于每个连通块，假设头号节点是黑点，dfs 一遍，再假设他是白点，然后 dfs，记录下来。将最大值和最小值分别相加，就能得到人数总数的最大值最小值，也就是 B 校的规模。

DP

我们开个 dp[i][j] 表示前 i 种食材，重量为 j 的情况下，价值最大是多少
转移方程：
dp[i][j] = max(dp[i - 1][j], dp[i - 1][j - w[i]] + v[i])
而 w[i] = a[i] - b[i]
v[i] = a[i] + b[i]
在 j < w[i] 的情况下直接继承 i - 1
但是就有一个很严重的问题（这道题的难点）
那就是 w[i] 可能为负数
第一种情况：j - w[i] > j，由于 j 最大到 100000，而 w[i] 最小 -500，所以数组要开到 100505 才可以。
第二个影响，由于 w[i] 可以为负数，所以其实可能出现 j 为负数的情况，我们发现 w[i] 的和最小为 50000，所以我们把所有 j 都加上 50000，这样就能避免 j 为负数的情况
可得 dp[0][50000] = 0
其他 dp[0][j] = -inf
cout << dp[n][50000] 就可以了
（50000 指代的是原来的 0）

D - Neighbor Distance
通过 map 来维护一下每个人的位置与离邻居最短的距离，每次一个新人来时，更新他左右两个人与他自己即可。

for (int i = 1; i <= n; i++) {
    int x;
    cin >> x;
    auto r = a.upper_bound(x); //获得他的右边
    auto l = prev(r); //获得他的左边
    int resl = x - l->first; //求出与左边的距离
    if (!l->second || l->second > resl) { //如果左边暂时没有邻居或者邻居距离没有这个长
        ans += resl - l->second; //x 就是他最短邻居
        l->second = resl; //更新
    }
    if (r != a.end()) { //先判断右边存不存在
        int resr = r->first - x; //求出与左边的距离
        if (r->second > resr) { //同上
            ans += resr - r->second;
            r->second = resr;
        }
        resl = min(resl, resr); //顺便计算出 x 离哪一个更近
    }
    ans += resl; //更新答案
    a[x] = resl; //放入 x 
    cout << ans << '\n';

C - Candy Tribulation
首先观察到一个性质：
假设有一个小盆友 i，x 是小糖果重量，y 是大的
a[i] 是小盆友想要吃的糖果数，w 是重量
设有 c1 个小糖果，c2 个大糖果
那么：
c1 * x + c2 * y = w
c1 + c2 = a[i]
如果说还有一个小盆友 j
d1 * x + d2 * y = w
d1 + d2 = a[j]
尝试将两式联立起来：
c1 = a[i] - c2
d1 = a[j] - d2
(a[i] - c2) * x + c2 * y = (a[j] - d2) * x + d2 * y
a[i]*x - c2*x + c2*y = a[j]*x - d2*x + d2*y
(a[i] - a[j]) * x = (d2 - c2)(y - x)
d2 - c2 = (a[i] - a[j]) * x / (y - x)
这样就求出两个人大糖果的差了
a[i] a[j] x y 都已知，所以只需要稍稍带入，理论上就能求出所有人的大糖果数量
（对，没想到吧，只要满足上面那个方程式，就能满足要求）
（所以小孩子们的糖果数量，只要差不变，就可以随便变动，可以自己试试）
最后剩下的就是后期了
我们令 j = 1
原式变为 d2 - c2 = (a[i] - a[1]) * x / (y - x)
为了确保 a[i] - a[1] 为正
将 a 从大到小排序
这样就可以求出所有人大糖果数量与第一个人的差
令他为 b[]
b[i] 表示的就是 i 所拥有的大糖果数量与第一个人的差
最后一点，也是我课上没搞懂的地方
就是求出第一个人的糖果数量
但是其实这个人的糖果数量（设为 v）是没啥限制的（因为差不变就可以嘛）
只有一个限制：
每个人的糖果数量不得大于 a[i]
这句话很好理解吧，题目里的
每个人的最大糖果数量是 a[i]
比第一个人多的糖果数量 b[i]
也就是说，第一个人的糖果数量不能超过 a[i] - b[i]
否则第 i 个人就会拥有多余 a[i] 个糖果，不满足要求
也就是说，v <= a[i] - b[i]
每个人的 a[i] - b[i] 都不同
第一个人的大糖果数量必须全部满足以确保所有人都合法
所以就可以取 min 啦
最后每个人的糖果数量就是 v 加 b[i]（除了第一个人自己是 v）
累加起来输出即可！

E - Clamp
对于每种询问，有两种情况
第一种（也是坑）：l > r
题目没说 l 不能 > r
当然这种情况也好做
想想公式：max(l, min(r, a[i]))
min(r, a[i]) 一定 <= r（否则为什么不取 r 呢）
l > r
所以 max(l, min(r, a[i])) 的结果一定是 l！
那么这个询问的结果就统统是 l * n
第二种：l <= r
答案由三部分组成
1. x < l，这时会给答案带来 l 的贡献
2. x >= l && x <= r 带来 x 的贡献
3. x > r 带来 r 的贡献
将每种数简单粗暴的开个桶分类讨论即可
具体做法？
开两个树状数组，一个 t1[] 存分布情况（统计数字种类），一个 t2[] 存存在的数字之和
lowbit update query seq 稍微改一下参数列表，使得能兼容两个数组
那么三部分的贡献就是
1. seq(t1, 0, l - 1) * l
2. seq(t2, l, r)
3. seq(t1, r + 1, MAX) * r
树状数组在下标为 0 时会产生死循环，所以需要加一个坐标偏移
那么三个贡献也要变：
1. seq(t1, 0, l) * l
2. seq(t2, l, r) - seq(t1, l, r)
3. seq(t1, r + 2, MAX + 1) * r

本题与那个很像

假设高桥最开始的位置位于 h0

如果高桥飞行 t 时后的高度为 h1，则
h0 - t <= h1 <= h0 + t
考虑到不能触地，并且简单推算易得往 1e9 以上的高度飞行是没有意义的
所以
max(h0 - t, 1) <= h1 <= min(h0 + t, 1e9)
令 a = max(h0 - t, 1)，b = min(h0 + t, 1e9)
则 t 时的飞行高度可能区间为
a <= h1 <= b

l1 <= h1 <= u1
故此，h1 实际上合法的区间是 [a, b] 和 [l1, u1] 的交集
如果没有交集，就说明不可能合法，直接输出 No 并结束
接下来怎么办呢
先把交集更新到 a 和 b 里，然后再继续循环即可
这样程序就可以自己推出下一轮 t2 时我们的飞行高度在合法的情况下可能为多少

for (int i = 1; i <= n; i++) { 
    int c = t[i] - t[i - 1]; //处理飞行时间
    a = max(a - c, 1ll); //飞行的最低可能高度
    b = min(b + c, MAX); //飞行的最高可能高度
    a = max(a, l[i]); 
    b = min(b, u[i]); //求与目标的交集，顺便保存到 a 和 b 里
    if (a > b) return 0; //如果无交集，return false
}
return 1; //全部合法，return true
这里很容易忘记取交集，直接用目标区间作为可能区间去算（比如我）
但是目标区间与可能区间可能并不是包含关系，也就是说，如果直接用目标区间的话，很容易出现“看起来能够达到，实际上达不到”的情况
在此举个例子
t = 1
n = 2, h = 1
2 3 13
3 10 13
如果像我以前那样直接用目标算的话
程序会认为可以完成 2 目标
而 2 目标又和 3 目标有交集
程序觉得 2 目标可以完成，就是说高桥可以到达 2 目标的任何地方，于是程序觉得直接选择交集的位置往前冲就行了
所以程序认为可以完成 3 目标
但事实上，高桥只能到达 2 目标的最底下，并不能到达 2 目标的任何位置，而 3 目标的底部提高了很多，这就导致虽然完成了 2，但是没办法完成 3

P1395 会议
树的重心
树的重心的定义是重量最小的节点
一个节点的重量定义为删除此节点和所有与其有关联的边后剩下连通块的最大大小
故此，去掉树的重心后的连通块大小一定最小
一棵树可能有至多 2 个重心（如果有两个，则其相邻，很容易想到）
可以证明，树的重心的重量不超过树的节点总数的一半

《可以证明》
+--- - - - - - ->
| 考虑反证法，令节点 v 为重心，并且 v 的重量 k > n / 2
| 去掉 v 之后的连通块可以大致分为两类。一是 v 的所有子树，二是其余部分（也就是 v 的上面带上根节点的
| 其他子树的大连通块）。
| 再计算一下 v 的一个相邻父节点 u 的重量
| 如果删除 u，那么剩下的是 u 的子树（包括 v）与一个大连通块
| 大连通块的大小是 k - 1
| 子树大小不可能超过一半
| 这也就意味着，u 的重量 < v 的重量
| 与 v 是重心矛盾，得证
+--- - - - - - ->

树还有一个性质，就是所有节点到树的距离和最短
因为这个和连通块有很大关系（连通块一定是树，那么在节点有限的情况下，高度也有限）
所以也非常容易证明
大家自己证证看吧，我这里就不《可以证明》了
好的那么我们就可以用这个性质 2 解这道题
通过写一个 dfs 来维护每个节点的重量，最小值即为重心
再写一个 dfs 计算距离和

g[i][j] = min(g[i][j], g[i][k] + g[k][j])
本题要求传递闭包，只需要判断连通性，故：
g[i][j] |= g[i][k] & g[k][j]

答案：bitset 优化！
我们强行列一个转移
g[i][j] = {
    g[i][j] | g[k][j]   g[i][k] == true
    g[i][j]             g[i][k] == false
}

那如果我们拿到了一个 bitset，直接 g[i] | g[k] 就行了

E - Minimum Swap
置换环
由于置换环交换两个点会形成两个环，而我们的目的是排好序，也就是形成 n 个自环，所以我们一定要交换两个点，这样可以多个环
交换两个点的顺序其实是无所谓的，所以只需要随便选置换环上的两个点交换就可以啦
每个环大小为 len，选两个点的总方案数为 C{len}{2}，也就是 len * (len - 1) / 2
记得 long long
signed main() { //置换环
    cin >> n; //输入 n
    for (int i = 1; i <= n; i++) cin >> a[i]; //输入 a[i]
    for (int i = 1; i <= n; i++) {
        if (vis[i]) continue; //避免重复访问，提高效率
        int x = i, len = 0; //定义 x 为当前节点，len 为置换环长度
        vis[x] = 1; //记录一下
        do { //这里使用 do-while 是因为最开始的 x 本来就是 i，如果不 just do it，循环就不会执行
            x = a[x];
            vis[x] = 1;
            len++;
        } while (x != i); //x = i 说明回来了
        ans += 1ll * len * (len - 1) / 2; //Cn2，答案贡献
    }
    cout << ans; //输出答案
    return 0;
}

mod: 链式前向星
第一次写专属模板日记
这是因为主题库没有链式前向星的模板
https://www.luogu.com.cn/problem/U81206
这是一个大佬自己提供的模板题

开讲啦！！！----------------------------------
链式前向星比 vector 难写
当然只难写一点点
而且比 vector 快超级多
能够提供很快的增删查改
性价比很高
所以题解都在用
其实很简单，就是把一个节点的所有出边当作一些元素存在一个链表里
以节点 u 举例
我们给每条边分配一个下标
head[u] 表示存边的链表里第一条边的下标是什么
然后边结构体，上！
Edge {
    to：表示 v（额
    w：顾名思义（额额额
    nxt：表示在链表中 ta 的下一条边是谁（下标
}
很简单把
事实证明，在边结构体是不需要存储这条边的下标哒！
为什么呢，因为 edge[下标] = 这条边，很明显可以直接查，不需要额外存
现在我们来加边……
怎么加呢
首先我们得有一个类似队列的下标在手对吧（cnt
每次加的时候我们就先 ++cnt，并将 cnt 作为这条新边的下标
++cnt; //过于简单了把
然后把这条边的 to 和 w 存了
g[cnt].to = v; //改了个名嘿嘿
g[cnt].w = w;
//这里默认链表名字为 g（struct Edge {...} g[];），你们也可以取别的名
然后将它放在链表头部
因为放在头部最简单，因为我们时是知道头部下标的
而由于你不知道尾部下标，所以放在末尾很难
链表的一个特性就是插入非常简单!!!
g[cnt].nxt = head[u]; //先把他的后面连到原来的头部
head[u] = cnt; //然后他就变成头部了
//注意噢！！head[] 数组是以 u 为下标的，而不是边的编号！！因为 head[] 存的是 u 的出边在链表中的头部编号！
于是我们得到了
void add(int u, int v, int w) {
    g[++cnt].to = v;
    g[cnt].w = w; //如果题目指出是无权图可以不写
    g[cnt].nxt = head[u];
    head[u] = cnt;
}
没那么难吧（°v°），只有四行！
而且现在，我们如果要加 u -> v 权值为 w 的边就可以直接
add(u, v, w);
了！
加边好了，现在我们来遍历
一般来说，无论是最短路还是什么东西，需求就一个：遍历 u 的所有出边
如果你不相信，可以去看看你的模板
那么在链式前向星中，如何遍历 u 的所有出边呢？
我们以前学过链表的遍历方法，只需要获得一个链表头，然后我们不停地取这个节点地 nxt，就能一个接一个遍历完
因为 nxt 就像一个箭头，指向下一个节点，你不停走箭头，走着走着就走完了
在链前中，我们的头节点是 head[u]
那我们只需要从 head[u] 开始，一直跳 nxt 就可以了！
当然，如果说跳到了 0，就说明上一条边的 nxt = 0，我们知道 nxt = 0 说明这条边压根没有下一条边，所以跳到 0 就要退出循环了！
所以遍历出边就可以这样写：
for (int i = head[u]; i; i = g[i].nxt) {
    int v = g[i].to;
    int w = g[i].w;
}
就是这样！
这里为什么不写 i != 0，而是写 i 呢，因为直接写 i 可以让编译器认为这是一个条件，如果条件的值为 0，那就返回 false，其他时间都返回 true，所以这样可以实现和 i != 0 一样的效果，并且减小代码长度。
好的，至此，我们已经啃下了一个链式前向星，相信现在你就可以去尝试用链式前向星来复刷那些最短路的题目了！

分类讨论整洁度为 2 的牛的数量 cnt2：
- 如果 $cnt2 = 0$，那么此时整道题的答案即所有牛的心情值总和。
- 如果 $cnt2 = N$，明显除了第一头洗澡的牛以外，后面洗澡的牛的心情值对答案的贡献系数均为 2。为了保证答案最大，我们肯定会把心情值最小的牛当作第一头洗澡的牛，免去它的贡献系数，以使得其它 $N-1$ 头牛的心情值均可以 ×2。那么此时整道题的答案即所有牛的心情值总和 ×2 − 心情值最低的牛的心情值，或者也可以记作所有牛的心情值总和 + 心情值前 $N-1$ 大的牛的心情值总和。
- 如果 $cnt2 \in [1, N-1]$，那么我们需要进一步分类讨论这 $cnt2$ 头整洁度为 2 的牛的心情值分布情况：
  - 如果这 $cnt2$ 头整洁度为 2 的牛恰好也就是心情值最大的 $cnt2$ 头牛，那么此时心情值前 $cnt2$ 的这些牛当中一定会有一头牛对答案的贡献系数取不到 2。为了保证答案最大，我们可以选择把心情值第 $cnt2$ 大的牛作为第一头洗澡的牛，让其贡献系数为 1，其余 $cnt2-1$ 头整洁度为 2 的牛贡献系数为 2。

E - A > B substring
这次 abc 的 C 是贪心，D 是 dfs，都很简单，赛事 AC，赛事卡了的是 E 题，所以直接讲 E。
E 题主要是一个经典转化，如果记住了在考场上也很有帮助。
我们先梳理一下，就是在一段区间里面的 A 数量 > B 数量，问你这样的区间有多少个
- 第一步转化：将比大小转化为判断区间和正负
这一步转化 OI 界也非常经典了
A 数量 > B 数量，也就是 A 数量 - B 数量 > 0
我们把字符串转化为一个序列 a[]，把字符 A 作为 1，B 作为 -1，C 作为 0
这样，区间和就是 A 数量 * 1 + B 数量 * -1 + C 数量 * 0
= A 数量 - B 数量
跟我们刚才推的一致
所以问题转化成了，在这样一个 a 数组里，有多少个区间和 > 0
- 第二步转化：将区间和转化为前缀和的差值
这也很经典
看到区间和，大家心里第一个想到的肯定是我们怀念的 sum[] 数组
一段 [l, r] 的闭区间和就是 sum[r] - sum[l - 1]
而如果要让区间和 > 0，也就是 sum[r] - sum[l - 1] > 0
问题又转化成了，求有多少对 (l, r)，使得 sum[r] - sum[l - 1] > 0
- 最后一步转化：将前缀和差值转化为逆序对
好的，我们已经接近真理了
我们上次把比大小转化成了差
那我们这次也尝试把差转化为比大小
sum[r] - sum[l - 1] > 0
则 sum[r] > sum[l - 1]
欸，这不
顺序对！
呃呃呃，其实就是逆序对的另一种形式啦
我们的问题变成了，有多少对 (l, r) 满足 sum[r] > sum[l - 1]
各位 OIer 肯定火眼金睛一眼看出本质上其实就是
有多少对 (l, r) 满足 a[r] > a[l]
这不逆序对
好的逆序对都出现了，树状数组肯定得安排一个
（别说我为什么不写归并，因为归并模板早就忘干净了，现在 sort 才是王道）
这里的离散化有一些小细节，由于我们转化是 sum[l - 1]，而 l - 1 可能 = 0，所以这里一定要记住离散化时将 a[0] 也加进去，由于有了下标 0，为了防止 lower_bound 返回 0 导致树状数组 lowbit(0) 直接死掉，我们需要额外 + 1 避免一下。离散化完了之后记得 update(a[0])，因为 l - 1 可能为 0，所以需要将 a[0] 设为 1，让后面不漏掉前缀的情况

ABC445 F - Exactly K Steps 2
给大家解释一下题意
就是对于每个点 a，走 K 步后回到原点 a 的代价最小是多少
矩阵快速幂（没想到吧，连图论都能加速，矩阵快速幂 yyds）
我们令 dp[k][i][j] 为从 i 走到 j，经过 k 步的最小代价
则 dp[k][i][j] = min(dp[k - 1][i][u] + dp[1][u][j])
发现这一点跟矩阵乘法很像，不过数值的相乘变成了相加，而最终结果变成了取最小值
我么将 k 视为一个指数
发现他完美符合数学乘法的性质
比方说
dp[k] = dp[k - 1] + dp[1]
dp[k] = dp[k / 2] + dp[k / 2]
你将其视为一个乘法
dp^k = dp^(k-1) * dp^1
dp^k = dp^(k / 2) * dp(k / 2)
是不是非常河狸
那就可以用快速幂来加速
直接解决
注意要开 long long，而且由于要取 min，最开始矩阵得赋成一个极大值，不要用 0x3f3f3f3f，因为那只适用于 int，如果说想要不麻烦，就 0x3f3f3f3f3f3f3f3f（8 个 3f）即可。
因为如果你开了 long long，默认就是 8 字节
所以 memset(0x3f) 就行了，自动适配 long long

P10726 [GESP202406 八级] 空间跳跃
主要思路有最短路和 DP，我这里选择了 DP。
DP 四部曲
状态，转移，边界，答案
题目给出的木板不一定按高度排序，我们排个序
S 和 T 都得重新赋值为排完序后的下标
设 dp[i][0] 表示走到 i 挡板左侧的最短时间
dp[i][1] 表示走到 i 挡板右侧的最短时间
设 j 为在 i 下面第一个可以到达的挡板
令 d = h[i] - h[j]（也就是跳下去所需的时间）
则必须满足两个条件之一（或全部满足）
l[j] <= l[i] && r[j] >= l[i]
这是可以从 i 的左端点跳到 j 上
此时的转移方程为
dp[j][0] = min(dp[j][0], dp[i][0] + (l[i] - l[j]) + d);
dp[j][1] = min(dp[j][1], dp[i][0] + (r[j] - l[i]) + d);
l[j] <= r[i] && r[j] >= r[i]
这是可以从 i 的右端点跳到 j 上
此时的转移方程为
dp[j][0] = min(dp[j][0], dp[i][1] + (r[i] - l[j]) + d);
dp[j][1] = min(dp[j][1], dp[i][1] + (r[j] - r[i]) + d);
边界条件
dp[s][0] = 0;
dp[s][1] = r[s] - l[s];
很容易理解
最后是答案
一定要注意，答案我们不能直接对 dp[t][0] 和 dp[t][1] 取 max
因为题目要求的是跳到 t 上就行，不一定要走到某个端点
可以在循环 j 的时候作判断
如果满足要求的第一个 j = t，那么答案可以为 dp[i][0] + d 或者 dp[i][1] + d（取决于是从左端点跳还是右端点跳）
核心代码
cin >> n >> s >> t;
for (int i = 1; i <= n; i++) {
    int l, r, h;
    cin >> l >> r >> h;
    p[i] = {l, r, h, i};
}
sort(p + 1, p + n + 1);
for (int i = 1; i <= n; i++) {
    l[i] = p[i].l;
    r[i] = p[i].r;
    h[i] = p[i].h;
    if (p[i].id == s) s = i;
    if (p[i].id == t) t = i;
    dp[i][0] = dp[i][1] = INF;
}
dp[s][0] = 0;
dp[s][1] = r[s] - l[s];
for (int i = s; i > t; i--) {
    for (int j = i - 1; j >= t; j--) {
        int d = h[i] - h[j];
        if (l[j] <= l[i] && r[j] >= l[i]) {
            if (j == t) ans = min(ans, dp[i][0] + d);
            dp[j][0] = min(dp[j][0], dp[i][0] + (l[i] - l[j]) + d);
            dp[j][1] = min(dp[j][1], dp[i][0] + (r[j] - l[i]) + d);
            break;
        }
    }
    for (int j = i - 1; j >= t; j--) {
        int d = h[i] - h[j];
        if (l[j] <= r[i] && r[j] >= r[i]) {
            if (j == t) ans = min(ans, dp[i][1] + d);
            dp[j][0] = min(dp[j][0], dp[i][1] + (r[i] - l[j]) + d);
            dp[j][1] = min(dp[j][1], dp[i][1] + (r[j] - r[i]) + d);
            break;
        }
    }
}
if (ans == INF) cout << -1;
else cout << ans;

P6456 [COCI 2006/2007 #5] DVAPUT
事实上觉得难度其实没有绿
直接哈希
这里的出题人非常的善良，并没有卡单哈希，甚至没卡自然溢出哈希，故我们使用自然溢出哈希来做（也就是 ull）
我们这里用自然溢出哈希做一个前缀哈希，然后后面就可以 O(1) 求区间
然后我们发现这个答案一定满足单调性
就是如果一个长度能被满足，那么比这个长度短的长度也一定能被满足
故二分答案
然后去枚举并统计哈希值出现次数
如果有一种区间哈希值出现次数超过 1，就说明合法
时间复杂度 O(n log n)
贴一下 check
bool check(int x) {
    unordered_map <ull, bool> mp;
    for (int i = 1; i + x - 1 <= n; i++) {
        ull h = hsh(i, i + x - 1);
        if (mp[h]) return 1;
        mp[h] = 1;
    }
    return 0;
}
这里使用 unordered_map 的原因是因为这题卡 map
map 基于红黑树（一种平衡树），是稳定的 log n 复杂度，在这题会被卡掉
而 unordered_map 使用哈希，牺牲了稳定性与有序性，换来了每次近 O(1) 的时间
也因为使用哈希，我们说他不稳定，他可能会哈希冲突，理论上最严重时可能会降至 O(n)
但是人家作为 STL 还是做了很多优化的，所以平时不用管那么多，用就是了
AC.

unordered_map 还有一个比较坑人的点被我这次遇到了
如果说你在使用 unordered_map 的同时还使用双哈希，这个时候你的代码大概会是这样
unordered_map <pair<int, int>, bool> mp;
如果直接这样写会报错，报很长
这是因为我们前面说过 unordered_map 基于哈希，然后他并没有封装一个 pair 的哈希
所以哈希函数要自己写
比方说
struct pair_hash {
    template <class T1, class T2>
    std::size_t operator()(const std::pair<T1, T2>& p) const {
        auto h1 = std::hash<T1>{}(p.first); // 对第一个元素计算哈希值
        auto h2 = std::hash<T2>{}(p.second); // 对第二个元素计算哈希值
        return h1 ^ h2; // 合并两个哈希值
    }
};
这种计算方法
最后直接
unordered_map <pair<int, int>, bool, pair_hash> mp; 即可
这个模板是泛型仿函数，意思就是 pair 参数填什么都能正常运行，如果不喜欢泛型的话，可以
struct pair_hash {
    int operator()(const std::pair<int, int>& p) const {
        return p.first ^ p.second; // 合并两个哈希值
    }
};
短小很多，但是代价是只支持 int
另外这个模板只是为了说明如何定义哈希函数，这个异或哈希是可以换掉的（冲突随处可见）

P3449 [POI 2006] PAL-Palindromes
其实本来是紫的，但是有个人发现了一个极其简单的做法，故降绿
两个回文串 s 和 t 连起来是回文串的条件当且仅当 base ^ |s| * hash(t) + hash(s) = hash(t) + base * |t| + hash(s)。也就是拼起来后正反的哈希都相同。
来整一下这个式子

base^|s| * hash(t) + hash(s) = base^|t| * hash(s) + hash(t)
base^|s| * hash(t) - hash(t) = base^|t| * hash(s) - hash(s)
(base^|s| - 1) * hash(t)     = (base^|t| - 1) * hash(s)
(base^|s| - 1) / hash(s)     = (base^|t| - 1) / hash(t)
发现这两个值相互独立，也就是我们完全可以预处理出这些值，然后 map 统计个数加起来即可。
注意除法要用逆元，本题卡单哈希，所以要用双哈希。

注意啊，我们这里有三种方法可以做他。

--- 倍增法
跟以前一样，dfs 求出 fa 存 st 表，然后补全 st 表，在 LCA 的时候直接 u 和 v 往上倍增跳就行了，时间复杂度 O(n log n)，常数中等。

这个 tarjan 和缩点用的 tarjan 没有任何关系（除了都是 tarjan 发明的）。
对图进行 dfs，每次都对下面的 v 与当前节点合并于并查集，然后判断有没有询问的节点都被这样处理过了，如果有，就直接输出他们的 find()，就可以了。

P13020 [GESP202506 八级] 遍历计数
讲一种比顶部题解写的短很多的思路
其实主要的主旨差不多
来研究一下 DFS 序的性质
令 f[u] 为以 u 为根的子树中的 dfs 序数量
易得 f[u] = (u 的直系子节点数量)! * f[u 的所有子节点] 的积
就是一个乘法原理，先选择顺序，再递归计算
瞪眼法易得：
f[s] 为所有 u 的直系子节点数量的阶乘
至于如何证明……
由于每个节点都会把自己的阶乘与下面子节点他们的阶乘贡献上去
所以其实根就是阶乘之积
要是写成数学形式：
f[s] = prod(i = 1 ... n AND i != s, (deg[u] - 1)!) * deg[s]!
其实就是因为根节点的度数就是其孩子数量，而其他的节点度数是孩子数量加 1（1 来自父节点）
继续转化：
f[s] = prod(i = 1 ... n AND i != s, (deg[u] - 1)!) * deg[s]!
     = prod(i = 1 ... n, (deg[u] - 1)!) / (deg[s] - 1)! * deg[s]!
     = prod(i = 1 ... n, (deg[u] - 1)!) * (deg[s]! / (deg[s] - 1)!)
根据阶乘性质 x! = (x - 1)! * x 得
f[s] = prod(i = 1 ... n, (deg[u] - 1)!) * deg[s]
一棵有根树如此，而无根树无非就是把所有节点当作 s 算一遍这个然后加起来
前面的求积是个定值，所以乘法分配律，得到
ans = prod(i = 1 ... n, (deg[u] - 1)!) * sum(i = 1 ... n, deg[i])
直接预处理阶乘，然后枚举每个节点单独算上面两个东西，最后乘起来即可。
代码不长，所以秀一波代码：
signed main() {
    cin >> n;
    if (n == 1) {

        return 0;
    }
    for (int i = 1; i < n; i++) {

        cin >> u >> v;
        deg[u]++;

    }

P1080 [NOIP 2012 提高组] 国王游戏
贪心，不过不好想，得先推公式。
设相邻的两个大臣按国王距离远近分别为 x 和 x + 1。
易得到，0 到 x - 1 与 x + 2 到 n 的金币数与他们俩顺序无关，所以可以局部最优
令 s 为国王，第一个大臣直到第 x - 1 个大臣的手上 a 的乘积
他们获得的金币数分别为
x: s / b[x]
x + 1: s * a[x] / b[x + 1]
最大值：max(s / b[x], s * a[x] / b[x + 1])
考虑交换顺序
x: s * a[x + 1] / b[x]
x + 1: s / b[x + 1]
最大值：max(s / b[x + 1], s * a[x + 1] / b[x])
如果交换顺序更优，则有
max(s / b[x + 1], s * a[x + 1] / b[x]) < max(s / b[x], s * a[x] / b[x + 1])
max(b[x], a[x + 1] * b[x + 1]) < max(b[x + 1], a[x] * b[x])
b[x] < a[x] * b[x], b[x + 1] < a[x + 1] * b[x + 1]
所以得：
a[x + 1] * b[x + 1] < a[x] * b[x]
故，按照 a[x] * b[x] 排序即可得到最优解！

sum(k = 1 -> a[i]) C(a[i], k) * v[i]^k

(a + b) ^ x = sum(i = 0 -> x) C(x, i) * a^i * b^(x - i)

sum(k = 1 -> a[i]) C(a[i], k) * v[i]^k

sum(k = 1 -> a[i]) C(a[i], k) * v[i]^k * 1^(a[i] - k)

最后得到
(v[i] + 1) ^ a[i] - 1
简洁多了！

2^(S - a[i]) * ((v[i] + 1) ^ a[i] - 1)

考虑使用虚拟物品法（我自创的名字，不过 buylowsellhigh 也是这个套路，就命了个名）
如何虚拟一个物品 x 使得选取 x 相当于撤销了前面某个物品 i 的选择？

#include <iostream>
#include <queue>
#define int long long
using namespace std;
int n, k, a[300005], l[300005], r[300005], vis[300005], ans;

struct Cmp {
    bool operator()(int x, int y) {
        return a[x] < a[y]; //心贪
    }
};

priority_queue <int, vector<int>, Cmp> q; //优先队列

signed main() {
    cin >> n >> k;
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        l[i] = i - 1;
        r[i] = i + 1;
        q.push(i);
    }
    for (int i = 1; i <= k; i++) {
        while (!q.empty() && vis[q.top()]) q.pop();
        if (q.empty()) break; //挖的坑咋这么少
        int x = q.top();
        q.pop();
        if (a[x] <= 0) break; //不是干这行太坑人了赶紧跑路了
        ans += a[x]; //血赚！
        a[x] = a[l[x]] + a[r[x]] - a[x];
        q.push(x); //说话不能说太死
        vis[l[x]] = 1;
        vis[r[x]] = 1; //不能耍赖噢
        r[l[l[x]]] = x;
        l[r[r[x]]] = x;
        l[x] = l[l[x]];
        r[x] = r[r[x]];
        //直接把坑填平了
    }
    cout << ans;
    return 0;
}

            //如果种
            int up = s & (1 << j);
            int le = (!j) ? 0 : (s & (1 << (j - 1)));
            if (a[i][j] && !up && !le) {
                t = s;
                t |= (1 << j);
                pls(g[t], f[s]);
            }
            f[s] = 0;
        }
        swap(g, f);
    }
}

这里采用了 f g 交替式滚动数组提高可读性，这题不开滚动数组内存条会很伤心的
另外，这个代码是刷表法，简单来说，就是通过枚举轮廓线来确定新的 (i, j) 的方案数，但是轮廓线却是旧的
唯一两句更新轮廓线的就是
t &= ~(1 << j); 删除轮廓线旧的第 j 列
t |= (1 << j); 把 (i, j) 选上的时候添加进轮廓线
选上为 1，所以置 1
另外，根据轮廓线性质（可以观察前面的那个例子），老的 1 << j 就是 (i, j) 的正上方，而 1 << (j - 1) 就是 j 的左边，利用这个可以解决本题

P1521 求逆序对
这道题……
首先，我们令 dp[i][j] 表示长度为 i 的逆序对数量恰好为 j 的方案数
很明显，我们想从 i - 1 转移过来，怎么办？
考虑在 1 ~ i - 1 的序列里插入 i，显然，i 会与后面所有数产生逆序对，再加上原来的，就可以得到 j
转移方程即为 dp[i][j] += dp[i - 1][j - (i - k - 1)] （0 <= k < i） k 表示插入位置
显然，可以把式子优化一下
dp[i][j] += dp[i - 1][k] （j - i + 1 <= k <= j）
这个不能直接过，但是
这不就是纯纯的前缀和？！
考虑优化，先计算出 dp[i - 1] 的前缀和，然后
dp[i][j] = sum[j] - sum[j - i]
特殊的，当 j < i 时，dp[i][j] = sum[j]
#include <iostream>
using namespace std;
const int N = 100 + 5;
const int mod = 10000;
int n, k, dp[N][N * N], sum[N * N];

int main() {
    cin >> n >> k;
    dp[1][0] = 1;
    for (int i = 2; i <= n; i++) {
        sum[0] = dp[i - 1][0];
        int maxj = i * (i + 1) / 2;
        for (int j = 1; j <= maxj; j++) {
            sum[j] = (sum[j - 1] + dp[i - 1][j]) % mod;
        }
        for (int j = 0; j <= maxj; j++) {
            dp[i][j] = (sum[j] - (j - i >= 0 ? sum[j - i] : 0) + mod) % mod;
        }
    }
    cout << dp[n][k];
    return 0;
}

using namespace std;
const int N = 1000 + 5;
const int mod = 10000;
int n, k, dp[2][N * N], sum[N * N];
int *f = dp[0], *g = dp[1];

int main() {
    cin >> n >> k;
    f[0] = 1;
    for (int i = 2; i <= n; i++) {
        sum[0] = f[0];
        int maxj = i * (i + 1) / 2;
        for (int j = 1; j <= maxj; j++) {
            sum[j] = (sum[j - 1] + f[j]) % mod;
        }
        for (int j = 0; j <= maxj; j++) {
            g[j] = (sum[j] - (j - i >= 0 ? sum[j - i] : 0) + mod) % mod;
        }

    }

}（此为 P2513 代码）

void pushup(int u) {
    t[u].w = t[ls].w * t[rs].w;
    t[u].w_r = t[ls].w_r * t[rs].w_r;
}

void reverse(int u) {
    swap(t[u].w_r, t[u].w);
    t[u].rev ^= 1;
}

void pushdown(int u) {
    if (t[u].rev) {
        reverse(ls);
        reverse(rs);
        t[u].rev = 0;
    }
}

void build(int u, int l, int r) {
    t[u].l = l;
    t[u].r = r;
    t[u].rev = 0;
    if (l == r) {
        t[u].w = (s[l] == 'X' ? X : Y);
        t[u].w_r = (s[l] == 'Y' ? X : Y);
        return;
    }
    int mid = (l + r) >> 1;
    build(ls, l, mid);
    build(rs, mid + 1, r);
    pushup(u);
}

void update(int u, int l, int r) {
    int L = t[u].l;
    int R = t[u].r;
    if (L >= l && R <= r) return reverse(u);
    else if (R < l || L > r) return;
    pushdown(u);
    update(ls, l, r);
    update(rs, l, r);
    pushup(u);
}

void query(int u, int l, int r, Matrix& f) {
    int L = t[u].l;
    int R = t[u].r;
    if (L >= l && R <= r) {
        f = t[u].w * f;
        return;
    } else if (R < l || L > r) return;
    pushdown(u);
    query(ls, l, r, f);
    query(rs, l, r, f);
}

首先，虽然这个条件确实不满足充分性，但是不满足充分性的情况非常之少，概率不大（除非你特意举反例卡这个东西），因为点权纯随机，产生碰撞（即充分性遭到破坏）的概率有人计算约为 2 的 128 次方分之一。而且出题人也没有办法卡你的哈希，因为你的点权是纯随机的，他没办法预测你的点权。换句话说，他连你的点权都拿不到所以更不可能对照着你的点权精心构造数据来卡你。所以，这个算法你可以理解为是正确的，提交会通过。如果你提交之后发现没通过而代码又没有 bug 的话，那真的建议去买彩票了。

void pushdown(int u) {
    int l = t[u].l, r = t[u].r;
    int mid = (l + r) >> 1;
    if (!ls[u]) ls[u] = mknew(l, mid, 0, 0);
    if (!rs[u]) rs[u] = mknew(mid + 1, r, 0, 0);
    if (t[u].lzy) {
        t[ls[u]].lzy += t[u].lzy;
        t[ls[u]].w += t[u].lzy * (mid - l + 1);
        t[rs[u]].lzy += t[u].lzy;
        t[rs[u]].w += t[u].lzy * (r - mid);
        t[u].lzy = 0;
    }
}

怎么办呢？

最终，由于上一轮 kruskal 选择了至多 n - 1 条边，加上新边 n 条边，时间复杂度变成了 O(nm)
